How to read this dashboard. nodeguard is an XDP firewall in the NIC driver, fed by a passive Suricata IDS. Everything fails open: an empty graph or a dead component means traffic flows unfiltered, never an outage.

firewall attached? "attached" = the XDP program is loaded and enforcing; "detached" = no enforcement; "unknown" = the tooling cannot verify state. kill switch: 0 = enforcing, 1 = soft-off (run nodeguard-on to re-arm). active blocks: entries currently in the block maps. responder unit: the Suricata-alert-to-block daemon.

XDP drop rate: packets per second dropped in-driver from blocklisted sources; nonzero means an active block is being exercised. XDP pass rate: internet traffic from globally routed sources surviving to the blocklist check; near zero on the remote node is normal, it only sees its own return traffic. Active blocks: block-map population over time; entries expire in-kernel by TTL. Suricata kernel drops: capture ring overflow, cumulative; a climbing line means reduced detection coverage, not a traffic problem. Allowlist / WireGuard pass rates: traffic taking the never-blockable paths (private ranges, operator addresses, and the tailscale tunnel port).
