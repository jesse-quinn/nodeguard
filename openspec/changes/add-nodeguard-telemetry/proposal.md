# Proposal: add-nodeguard-telemetry

## Why

nodeguard's monitoring chain undersells the datapath it watches. Only 5
of the 8 kernel stats slots are exported, and the exporter's fallback
paths coerce read failures to zero (nodeguard-status:65-73 prints
ng.pass=0 on a parse failure; nodeguard-status:93 coerces a wedged
suricatasc to kernel_drops=0), so a broken collector is
indistinguishable from a quiet network. There is no security-event
visibility at all: no scan or protocol-anomaly counters in the kernel,
no responder activity fields, no Suricata alert rate. Map utilization,
sweep health, watchdog internals, and dispatcher identity
(prog_match/attach_mode) are unmeasured, so the operator learns about a
filling LPM trie or a drifting attach from an outage. The only
dashboard lives in a private script that hardcodes the two host names
and delete-and-creates by name, so it cannot scale to a third host and
cannot be reviewed in the repo. docs/design.md predates the feeds
change and still claims risks the tree has since resolved.

## What Changes

- New count-only kernel map `stats2` (PERCPU_ARRAY, 16 slots, 7 live):
  TCP flag-combination, low-TTL, and fragment counters, counted before
  the kill-switch gate so scan visibility survives a latch. Every new
  branch resolves to XDP_PASS; no new drop path.
- Full kv export with a uniform fail-to-unsupported discipline: all 8
  stats slots, stats2, rearm_count, prog_match/attach_mode, watchdog
  internals, responder fields, and suricata_alerts; a value that cannot
  be read is omitted (item goes unsupported) plus an explicit fail flag
  where a local tool broke. Silent-zero fallbacks are removed.
- Sweep-cached map statistics: the 10-minute sweep becomes the single
  writer of /var/lib/nodeguard/mapstat.kv (counts, utilization,
  hits-delta top-blocked, walk duration); the 1-minute kv path becomes
  O(1) in blocklist population, and reboot truncates the cache so it
  reports unknown instead of stale totals.
- Two deliberately redundant anomaly layers: a gateway-local EWMA
  detector in the watchdog (shadow mode first; excluded-cycle updates,
  regime reseeds, bounded adaptation; never mutates enforcement) and
  Zabbix baselinedev plus static-ceiling triggers with a 14-day
  reviewed-quiet promotion gate.
- Zabbix template v2: one master item (nodeguard.kv.raw) with all
  existing and new items as dependents, generated by zbx/gen-template.py
  with uuid and display-name carry-over from the committed v1 (no
  itemid churn, no history loss), plus LLD for the per-feed dimension.
  A scratch-template import rehearsal gates the live import.
- Three dashboards (Overview, Security, Capacity and Pipeline) generated
  from a new public zbx/ suite; the Zabbix host group is the fleet
  definition, widgets are group- or pattern-addressed, and adding a
  host is a generator re-run, not a code edit. Host names, prefixes,
  and URLs stay in the private wrapper.
- deploy.sh gains --with-kernel: default deploys touch no kernel object
  or map spec, so a userspace phase can never activate an untested
  datapath via a restart; build.sh, reload, and attach derive the map
  list from the object instead of hardcoded six-map lists.
- Complete documentation refresh: design.md re-read section by section
  against the tree, ADRs 0006 and 0007, CHANGELOG back-fill, README,
  legend.html rewrite, env and project.md updates.

## Impact

- Affected specs: new capability `telemetry-observability`.
- Affected code: src/nodeguard_kern.c (stats2 map, sanity counters,
  kill-switch check relocation); build/build.sh (derived map list at
  lines 30, 47, 84 plus BTF assertions, netns rehearsal additions);
  deploy/deploy.sh (--with-kernel, agent conf staging);
  bin/nodeguard-reload and bin/nodeguard-attach (generalized identity
  check, pre-load spec guard); bin/nodeguard-lib.sh
  (ng_verify_map_identity); bin/nodeguard-status (full kv export, fail
  flags, cache-sourced counts); bin/ngmap.py (stats2 subcommand, sweep
  cache accumulation); bin/nodeguard-watchdog (EWMA anomaly layer, wd_*
  export); bin/nodeguard-responder (responder.kv); bin/nodeguard-feeds
  (post-apply sweep trigger, per-feed emission gating);
  units/nodeguard-sweep.timer (OnBootSec); nodeguard-maps (cache
  truncation); etc/zabbix-userparameter-nodeguard.conf; new zbx/
  directory (lib.py, dashboards.py, gen-template.py,
  check_template.py); templates/zabbix-nodeguard-template.json
  (generated v2); hosts/example-gateway/nodeguard.env; docs and ADRs
  per the design's section 11.
- Out of scope: per-source rate limiting (stays deferred per the
  roadmap), ringbuf event streams and LRU_HASH top-N maps,
  kernel.bpf_stats_enabled in any form, and any enforcement change of
  any kind (the anomaly layers observe and count only).
